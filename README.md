# Tuesday

Tuesday is an applicant-side evidence system, shipped first as a suite of Claude skills. The system's job: help a job seeker evaluate opportunities on evidence rather than vibes, recover truthful evidence their CV omits, prepare for real interviews, and never — at any point — coach a claim the evidence doesn't support.

Skills are the first surface. A later orchestrating agent is a stated destination of the same repository, consuming the same contracts (see *Repository shape* and *Licensing*).

## Why "Tuesday"

Tuesday is *Mangalvaar* in Hindi — the day of Mangal, which names Mars and is also a word for auspiciousness. An auspicious day belonging to the god of war is exactly this system's register: it puts the applicant on a deliberate, well-armed path to the right opportunity rather than a spray of hopeful applications — and the only ammunition it ever issues is verified evidence. (Job-market folklore also holds that postings and applications peak on Tuesdays; treat that as a wink, not a citation.)

## The one rule

**Every skill stands alone.** Each runs to a complete, useful output from raw inputs (a JD, a CV, a prompt). Artifacts from sibling skills enhance; they never gate. Use one skill, use them all, use them in any order — the shared dossier makes order irrelevant, not mandatory.

## Watch-outs: what to double-check

Each skill ends its output with one sentence telling you what to double-check. Each one is there because we measured a problem in testing and could not fully fix it, so the skill tells you where to look instead.

| Skill | Watch-out | Why it's there |
|---|---|---|
| job-underwriter | A summary line here can contradict the evidence table — before you act on a count, an "only" or an all-clear, check it against the table's rows. | In testing, about one run in three still had a sentence about the requirements — a count, an "only", or an all-clear like "you clear every must-have" — that the evidence table below it did not bear out: 10 of 35 runs in the latest round, after four rounds of fixes. See "Counts, rounds 7 to 9" under [Tracked work](#tracked-work). |
| mock-interview | Suggested answers can make your experience sound bigger than what you told me — rehearse only what you actually did, in your own words. | Suggested answers sometimes stretch what you said by one step — "proposed" becomes "drove", or a habit you never mentioned appears. Fixes halved it, but it still happened in at least four test runs out of five on every test case. See "What was done about each" under [Tracked work](#tracked-work). |
| resume-tailor | The words I quote as yours beside each edit can differ slightly from what you wrote — before you approve a line, check that quote and the new line against your original resume. | The quotes of your own words beside each suggested edit came out slightly changed in about one test run in three (33%), across three separate batches of tests, even after a rule saying to quote word for word. That was measured in September 2026, after one fix, and has not been measured since. See "Cross-set recurrence" under [Tracked work](#tracked-work). |

**The rule behind this.** When two attempts to fix a problem have not fixed it, we do not try a third time. If you can protect yourself by checking something, that check goes into the skill's watch-out, and the problem stays on record below as open, with how often it happens. If you cannot — for example, if a skill does not start when it should — it goes to the maintainer as a decision instead. The full rule is in [`CONTRIBUTING.md`](CONTRIBUTING.md#when-an-issue-survives-two-iterations).

## The cloth

Coherence lives in [`conventions/`](conventions/) — canonical, and mirrored into each skill's `references/` with a synced-from header (canonical wins on conflict):

- [`evidence-conventions.md`](conventions/evidence-conventions.md) — evidence source types, confidence bands, the gap taxonomy, content provenance labels, and the mapping that connects them. The truthfulness core every skill is bound by.
- [`interaction-grammar.md`](conventions/interaction-grammar.md) — the standalone invariant, elicitation policy, degradation and upgrade menus, research tiers, privacy and scope, trigger hygiene.
- [`reframing-audit.md`](conventions/reframing-audit.md) — six axes of drift and five disciplines, covering every word a skill proposes the candidate say, write, or send. Canonical because it is not one skill's property: job-underwriter proposes resume lines and outreach phrasing, resume-tailor's whole output is proposed language, and two copies of it would diverge in exactly the two places it is load-bearing.
- [`output-discipline.md`](conventions/output-discipline.md) — seven rules on the shape of a delivered response, the first six each learned from a measured defect and the seventh the watch-out line every delivered output ends with. Each rule has an **invariant** the suite holds absolutely and, where variation is legitimate, a **parameter** each skill declares for itself, because the half that kept failing was never the number: two skills already said "at most three questions" and what broke was that a question inside a template did not feel like it counted. Skills declare their parameters in a `## Output discipline` block and CI fails a skill that omits one — a default nobody chose is the failure this file exists to prevent.
- [`citations.md`](conventions/citations.md) — the sources behind every figure, research finding, survey result and statement of law in the conventions, the skills and the specs, each quoted verbatim beside its URL and what weakens it. Prose cites an entry rather than paraphrasing it; CI checks each marked quotation against its entry and flags a source quoted, or paraphrased in quotation marks, without one — what it cannot see is in `CONTRIBUTING.md` — and `ci/verify_citations.py` checks every entry against its source.
- [`dossier-schema.md`](conventions/dossier-schema.md) — the versioned shared artifact: read-if-present, append-always-offered, never required. One writer per section; handoffs in both directions.

## Install

Per-skill instructions live in each skill's README. The short version:

- **claude.ai (web):** enable code execution (Settings → Capabilities), then Customize → Skills → upload the skill's zip. The zip root must be the skill folder itself.
- **Desktop app:** skills follow your claude.ai account (Customize in the sidebar); a shared `.skill` file card offers one-click Save.
- **Claude Code (CLI):** copy `skills/<name>/` to `~/.claude/skills/` (personal) or commit to `.claude/skills/` in a project. Also invokable as `/<name>`.

Prebuilt installables live in [`dist/`](dist/) (`.skill` files; rebuildable from source — may graduate to GitHub Releases).

## Repository shape

```
conventions/        canonical contracts — the cloth
skills/<name>/      self-contained skill packages (SKILL.md, references/, evals/, docs/)
evals/              suite-level evals — routing between skills, which no single skill can test
ci/                 repository checks, standard-library only, with their own self-test
dist/               built .skill installables
agent/              (reserved — does not exist yet; arrives when its trigger fires)
```

Skills are dependency-free by rule: nothing outside a skill's folder is required at runtime, because installation is per-skill. The conventions are therefore a canonical-plus-mirrors system, not a runtime import; mirror drift is a defect.

## Tracked work

- **Skill triggering strength — measured across three skills, and my own explanation for it was wrong.** With two skills the rates were lopsided: job-underwriter 10/12 of its own reserved phrasings, mock-interview 2/12. This ledger recorded the obvious reading — that the two compete, and mock-interview's rate tracked how assertive job-underwriter's description was, since it moved when job-underwriter's changed and not when its own did. Adding a third skill falsifies it. mock-interview went **2/12 → 7/12 without a word of its description changing**, job-underwriter 10/12 → 7/12, resume-tailor arrived at 4/12. The rates converged rather than compounding, which a competition model does not predict. The honest reading now is that each skill fires around half the time on its own reserved phrasings, that the two-skill split was a smaller sample than it looked, and that I do not have a mechanism — only a measurement. Spanning requests remain the weakest case at 1 reach in 9.
- **No over-triggering, and no confusion between skills — 63 runs, three skills.** Every near-miss negative held: 18/18 across six cases, including the two sharpest in the set, a template redesign and a proofread that wear resume-tailor's exact vocabulary. And **not one run in the entire suite has ever fired the wrong skill.** The model is not mixing these up; where it fails, it answers directly instead of reaching for any of them.
- **Three-way trigger boundaries — measured, and the answer is to change nothing.** `interaction-grammar.md` §6 carries resume-tailor's row; job-underwriter's and mock-interview's boundaries still name only each other, and stay that way. The reason to add a third exclusion to each would be cross-firing, and there is none to fix — while the cost is well evidenced, since this suite has already watched a more assertive description move its sibling's rate. Reserved decisions get made on measurement or not at all.
- **Provenance labels — closed, structurally.** Four prose rules failed to keep `[grounded]`/`[inferred]`/`[generic]` attached to derived claims. What worked was giving the label a column: role reality and the application plan are now tables with a Provenance cell, and graders report the labels present in every run of every section that has one. **This entry named a third table it should not have.** The opportunity risk register carried no Provenance cell when this entry was written — f97ba26 gave it one — and the claim that it did stood here unchecked until a grader pointed at the register's hypotheses as the unlabeled world-claims they are. The general finding is worth more than the fix — **where a section is a table the rule holds; where it is prose, four rules across four commits could not make it hold.** The corollary shipped with it: a label marks where a claim about the *world* came from, not the skill's reasoning about its own analysis, and the test is whether the sentence would still assert something if the analysis were deleted.
- **Clean-room failures are classified, not counted.** `run_fixtures.py` runs each fixture once, re-runs any fixture that failed something twice more, and reports each failure as `deterministic` (failed every run) or `intermittent`. On its first real use that separated 1 real defect from 7 draws on 14 executions rather than 24 — and caught two contradictions between rules I had written myself, both invisible while every failure looked alike. mock-interview eval 5, the fixture this ledger flagged as unstable, now reads 13/13 from both graders. Two harness lessons are in `evals/README.md`: grade the artifact rather than the cover note, and never let a grader that returned nothing count as a run in which everything failed.
- **mock-interview's spec — written, and it found three things.** `docs/mock-interview-spec-v1.md`, versioned v1 rather than v0 because it describes a skill that already shipped. Writing it was not archaeology: the skill's own `n + x` rule opens *"the sections this skill's spec defines are n"* and had been pointing at a document that did not exist since the day it was written, which is exactly the blind spot the Step 1 defect lived in. Three gaps surfaced, all proposed rather than built: a pack made **without** a dossier has no prohibited-claims record, though the other two skills both maintain one locally and the same temptations exist; the drill's scoring rubric is specified somewhere the skill body never points at; and **loop mode has no fixture at all** — five cover session mode, none covers multiple scheduled rounds, which is the kind of gap that stays invisible until someone uses the feature.
- **Cross-set recurrence — a signal the runner is blind to, and it corrected me twice.** `evals/recurring.py` reads grade JSON that clean-room runs already wrote and finds expectations failing across *independent* run-sets. The runner classifies within one set, so a failure appearing once in every three runs reads as intermittent noise each time; holding at that rate across three sets is a stable defect. Two claims of mine did not survive it. The question-budget and sibling-count fixes went from deterministic to **50% across two sets** — real improvement, not the closure I reported. And resume-tailor's altered-quote failure sits at **33% across all three sets including the most recent**, where I had described it as fixed and dropped to intermittent. All three have now had one rewording and persisted, which by `CONTRIBUTING.md`'s own rule means the next fix changes the shape. The question budget has an obvious slot — number the questions and state the count, so counting is forced rather than remembered — and the other two do not yet.
- **Spanning and low fire rates — one explanation tested and falsified, the finding still open.** A diagnostic capture on case 21 showed the model firing job-underwriter, running `ls` for the promised JD and CV, finding none, and answering *"I don't see any attached files come through… once I have both I'll run the fit assessment first."* Right skill, right sibling order, scored `neither`. Six cases claimed attachments the harness never provided and reached a skill on 22% of runs against 55% for self-contained prose, so the obvious reading was that the prompts were lying to the model. The runner now materialises the documents — and it moved nothing: **22% before, 22% after, not one of six cases changed.** The correlation is real and the causal story was wrong. The better remaining hypothesis, untested, is that routing happens from the prompt text before any file is opened, and the attachment-claiming prompts are simply the ones carrying no domain content: case 17 is intent with no role in it, while case 1 — which fires every run — has a whole JD and CV inline. The attachment materialisation stays because a fixture claiming a file should have one, but it is a validity fix and not a performance one.
- **The suite's only 100%-persistent failure — halved, no longer deterministic, and it taught something better than the fix.** job-underwriter eval 2 #6 had failed 37 graded runs of 37 across nine run-sets. It bundles three requirements. The vocabulary two are closed: `gap_type: none` was declared in the skill's row spec, written by the worked dossier and carried in every envelope while the canonical vocabulary listed five tokens — a skill had quietly extended canonical and nobody noticed for four months, which is the drift `job-underwriter-build-brief.md` §7 exists to prevent — and `none/low` kept reaching a Confidence cell because three files said to put the qualifier in `reasoning`, **which was a field in the spec and in the JSON and not a column on the page.** The third requirement, provenance labels on world-claims, is now **7/14 at n=7 and intermittent** where it was 0/10 at n=5 immediately before, on a single controlled change. Two general findings came out of it, and both are worth more than the number. First, PR #7's rule turned around: *a destination a rule names must exist in the shape being written*, mechanised as `qualifier_fields` with CI checking each named field is a rendered column — it caught mock-interview's fit snapshot on its first run, a table that existed only as a sentence describing one, inside the cell warning that a column named and not rendered gets invented at write time. Second, and larger: **every free-text surface accumulates world-claims, and labeling one moves them to the next.** The migration is traceable across five run-sets — free prose everywhere, then the register's hypotheses, then the evidence map's reasoning cells, then the fit and opportunity ledger slots that replaced the snapshot's paragraph. Each was fixed by giving that surface a Provenance cell; each time the claims found the next unlabeled surface. That is why the rule is canonical as output-discipline rule 6 with `provenance_sections` declaring coverage, and why CI now cross-checks the two parameters: **a free-text column must sit in a table that also has a Provenance cell.** That check exists because the mistake was made twice in one session — the register's `Hypothesis` column was given a label after graders found it, and the evidence map's `Reasoning` column shipped bare in the same commit, which the next run-set's graders found six times over.
- **Small clean-room samples flatter, and this ledger nearly recorded one.** Three runs of eval 2 read 0/6 → 2/6 → 3/6 on the same expectation and looked like a clean trend; five runs read 0/10. The trend was noise and a "first" was claimed on it before the larger sample landed. `run_fixtures.py`'s deterministic-versus-intermittent split is only as good as the run count behind it, and three runs cannot separate a 50% failure from a fixed one. Anything reported as closed on three runs is reported too early — the number that stood up here took seven.

SKILL.md placed the gap recovery queue fourth of nine and each of its prose blocks carried its own `Question:` line, so the questions were followed by three more sections before the upgrade menu. Two rules broke on that one shape: `closing_order`, and the question budget, which says the count is taken across the whole message and that either the embedded prompts are the budget or the closing block is — this message had both. The queue is now a table whose rows say what each gap is and what would close it, with the question asked once in the closing block tagged to its row; one envelope entry, two placements. It went **6/14 → 14/14** and left the failure list entirely. The register one section below had carried its verification question as a column since v0.1, with a note explaining that as a prose line it survived only on entries that arrived with a worked example — same failure, same fix, one section apart and four months late. The queue was also the next unlabeled surface in the migration chain, so #6 moved **7/14 → 10/14** as an unpredicted side effect, and the fixture total reached **94.6%**, its highest, from 84.7% at the start of this work.
- **The same shape change, ported to a second skill, and measured there too.** resume-tailor's two largest recurring failures were the same defect job-underwriter's gap queue had: recall prompts carrying their own `Question:` line, counted against the closing block's questions. The rule against it was already written in the skill body and had been for three versions; it failed in half of all graded runs, because a `Question:` line inside a template does not feel like it counts. Removing the second site is what counting could not do. Eval 5 went **68–76% → 96.8%** and its question expectation **0–4/6 → 13/14**; eval 1 went **85–93% → 95.2%** and **3/6 → 9/14**. No grader reason now mentions question count on either fixture. The residue on eval 1 is the other half of a bundled expectation — an upgrade menu omitting one of three gaps — which was always there and is now the only thing left.
- **An eval and a declared parameter contradicted each other for two releases.** resume-tailor declares `closing_order: upgrade menu, questions`, so the questions come last; all five of its expectations demanded the response "closes with an upgrade menu", so the menu comes last. A grader enforcing the expectation fails a response that obeys the skill's own parameter, and one did. job-underwriter's wording — "the menu and the questions are the last two sections" — is what all five now say, though two of job-underwriter's own expectations carried the same contradiction beside it, unnoticed until a check looked. The contradiction predates the work that found it: the parameter landed in PR #7 and the expectations earlier still, and nothing checked an expectation against the parameter it is testing. `check_parameter_agreement` in `ci/check_skills.py` now does.
- **What stays worth something when a signal gets cheap.** `evidence-conventions.md` §5 gains a third override, on what `[generic]` may support. Its outside evidence is one study of an AI writing tool on one freelancing platform (cite C1) (cite C2) (cite C3); what the convention takes from it, and what it labels inference, are in that section and not repeated here — this ledger once restated the rule and the copy drifted from canonical within a commit. The override restates `evidence-conventions.md` §4 rather than adding a constraint. Its first draft was wrong: it forbade uses that section now names as legitimate, among them mock-interview's deliberate degradation, where a research-less pack labels its banks generic and says so. Whether any of this reaches this suite's users is unknown; there is no usage data.
- **Research depth has a rule, and it is not a budget.** `interaction-grammar.md` §4 described how much research may run and never what for, so a skill could spend L1's cap on questions whose answers changed nothing and be compliant. It now says a search that cannot change something the skill will actually emit — a row, a band, a gap type, a question bank, a persona weight, a guidance cell, a recommendation — does not run, whatever budget is left, and that list is deliberately every skill's units rather than one skill's. Paired with the distinction that makes the depth question answerable: **research what is published; never research what is presumed.** A company's published values page and an interviewer's public professional footprint are first-priority targets precisely because they are attributable and checkable, and mock-interview's checklist says they may never come from memory. Out of bounds at every tier is the presumed — what a manager "is really looking for", what an employer values in a candidate *absent a published statement*, what will "impress" this panel. What counts as inspectable proof in a domain is published in exactly that sense, and `evidence-conventions.md` §2 needs it to set bands correctly. The test is whether a reader could be shown where it came from.
- **A canonical file declared its own mirroring for four months and was mirrored by nobody.** `interaction-grammar.md` has opened with "skills mirror in `references/`" since it was written. No skill mirrored it. It surfaced only because new text in `evidence-conventions.md` cross-referenced it, putting a pointer to a missing file inside three mirrors — the same defect this suite had just spent a release fixing, committed inside the change meant to encode the lesson. The check that existed validated every mirror that *was* there and was silent about one that *should* be; the inverse check now exists, and the mutation proving it deletes a mirror. The general shape is the one this repository keeps rediscovering: a declaration nobody verifies is a decoration.
- **An adversarial review found ten defects in canonical text I had already reviewed myself.** The conventions change above was self-reviewed, found one real problem, and felt finished. A four-lens panel — self-violation, contradiction, inertness, overclaim — then found ten more, and the serious ones were collisions with rules the suite already had. The `[generic]` override as first written forbade the risk register's standing failed-attribution entry, which ships as `[generic] pattern for companies of this size, not a claim about this one` and caps the decision at `conditional_go`; it forbade the evidence map's reasoning cell, where `evidence-model.md` *requires* `[generic]` and calls the pull to write `[inferred]` the thing to resist; and it was violated by three worked examples shipped beside it. Recorded because the lesson is not "review harder": it is that a canonical file binds three skills that each already have rules, and the failure mode is not a bad rule but a true rule stated in one skill's terms.

This suite has enough real mechanisms to afford naming a gap instead of filling it with something wrong.
- **The second panel caught what the first did not: a rule with nowhere to land.** The depth rule said to skip a search that can change nothing "and say what was skipped", naming no destination — and every comparable bullet in the same file names one. That is this repository's own trigger word for word: compliance depends on noticing an absence, and a search that ran wastefully leaves a response byte-identical to one correctly skipped, so neither a reader nor a grader can tell them apart. It survived the first review and my own rewrite of the same paragraph. The skip now lands in a table — one row per declared target, ran or skipped, and for a skip the output it could not have moved — in mock-interview's Sources and job-underwriter's evidence status, with `n/a` then kept distinct from `no` because collapsing them hid the case the rule is about (the labels now are in `interaction-grammar.md` §4). The underwriter's first version put the slot only in its dossier template, which a run opens *before emitting a dossier* — an optional Step 4 — so an assessment delivered without one never met the rule at all; the spec now lives in Step 2, which every run reads, and the template renders it. resume-tailor declares no research tier at all, which was true and unstated: it mirrored the rule and could never fire it.
- **Four overclaims, in the file that defines the audit against them — and a fifth in the correction.** Summarising the paper behind the `[generic]` override, the first draft dropped the authors' hedge and widened their population inside an attributed sentence, a second asserted a share of this suite's users on no usage data, and the broader reading — that whatever becomes cheap to generate stops carrying information — was stated as a finding rather than labelled an inference. The lesson is the one that file exists for: a paraphrase and its source that sit in different files are never compared, and *verbatim* is a claim like any other — it needs the source beside it to be checkable.
- **Six dangling pointers, introduced by the commit that fixed dangling pointers.** Mirroring `interaction-grammar.md` into three skills carried its two references to `dossier-schema.md` along, and no skill held that file — the same defect as the unmirrored canonical, one level down, shipped inside its own fix. The schema is now mirrored and declares it, and CI checks the general case: a reference naming a canonical file its own skill does not carry is a pointer the reader cannot follow, because skills are dependency-free by rule.
- **The ledger asserted a rule and its retraction, four bullets apart.** The entry describing the research-depth change quoted "research the artifact vocabulary, not the employer's preferences" — a phrase that appears nowhere in the shipped convention, because the panels had already established it would break mock-interview's first-priority target and it was replaced by *research what is published; never research what is presumed*. The retraction was recorded correctly in a later entry, so both readings sat in one list, and `check_ledger` cannot see it — it detects duplicate and colliding titles, not a bullet contradicting a differently-titled successor. Fixed by rewriting the entry to describe what shipped. The general lesson is the one this release keeps producing: **the ledger is written about the conventions and nothing compares the two**, which is the same gap that let four overclaims through — a skill's output is graded and the documentation around it is not.
- **Canonical text named a skill-local file, three times, right after that class was fixed.** `evidence-model.md` belongs to job-underwriter alone. Canonical prose naming it is mirrored into all three skills, so mock-interview and resume-tailor carried pointers to a file they do not have — the same defect as the unmirrored canonical and the six `dossier-schema.md` pointers, in its third distinct form, committed in the change that fixed the second. The first panel had already named the general shape of this: **a true rule written in one skill's vocabulary.** The dangling-pointer check gated on `conventions/` membership and so was blind to it; it now gates on every filename the repo carries as a reference document, which catches all three forms and still ignores `tuesday-dossier.md`, an emitted artifact rather than a file to open.
- **A slot in a file the run never opens is not a slot.** The research accounting landed correctly in mock-interview, whose template is read on every delivery, and in resume-tailor, which declares no tier. job-underwriter got it only in `dossier-template.md` — read "before emitting a dossier", and the dossier is offered and often declined, so any assessment delivered without one never met the rule. Two canonical mirrors added the same day were listed in no skill's reference section at all: present, byte-identical, and named nowhere a run is told to look. That is the fourth form of one defect this release has now found — after the unmirrored canonical, the six `dossier-schema.md` pointers, and canonical text naming a skill-local file — and it runs in the opposite direction to the others, which is why the check built for them was blind to it. **A pointer to a missing file and a file no pointer reaches are the same failure**, and CI now checks both: every `references/*.md` must be named in its own `SKILL.md`, because a mention buried in a sibling is reachable only by someone already reading that sibling.
- **Nothing graded the conventions. Now the documentation is graded, and the checks have been reviewed as hard as the text.** What each check reads, and what it cannot, is in `CONTRIBUTING.md` under "The documentation is graded too"; this entry records what the work found. A manual sweep of the shipped reference files found seven outside claims with no source, and two were wrong as well once the sources were read (cite C23) (cite C25).
